# App Lock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An optional App Lock (off by default) that asks for the phone's own fingerprint, face or screen PIN before showing past writing or running data actions in Settings, so someone borrowing an unlocked phone can't read or wipe the journal.

**Architecture:** A `@Singleton` `AppLock` holds whether the lock is on (its own `lock_prefs` DataStore, so it's never in a backup) and whether this session is unlocked, relocking after 60 s in the background. A `DeviceAuthenticator` interface wraps `BiometricPrompt` (biometric or device credential) so logic is testable with a fake. One `LockedRoute` composable gates every locked destination in `AtaraxyNavHost` and sets `FLAG_SECURE` while it shows. Settings gets an App Lock switch and a guard that asks for the unlock before each data action.

**Tech Stack:** Kotlin, Compose Material 3, Hilt, DataStore Preferences, `androidx.biometric:biometric:1.1.0` (latest stable), `androidx.fragment:fragment-ktx:1.9.1` (latest stable; `BiometricPrompt` needs a `FragmentActivity`), JUnit 4 + Robolectric 4.17, Compose UI test.

**Spec:** `docs/superpowers/specs/2026-10-20-backup-lock-widget-lookback-privacy-design.md`, section 2.

## Global Constraints

- No `INTERNET` permission; backup rules unchanged; Room stays at version 3.
- New dependencies only: `androidx.biometric:biometric:1.1.0` and `androidx.fragment:fragment-ktx:1.9.1`, added through `gradle/libs.versions.toml`.
- The lock setting lives in its own DataStore named `lock_prefs`, never in `user_prefs` (so backups never carry it and restore never turns it on) and never in `backup_prefs`.
- Authenticators: `BIOMETRIC_WEAK or DEVICE_CREDENTIAL` (supported on API 29, the app's minSdk). "Can use App Lock" = `KeyguardManager.isDeviceSecure`.
- Relock after the app has been in the background for 60 seconds or more; a cold start is locked.
- Locked routes: `Screen.JournalHistory.route`, `Screen.PracticeEdit.ROUTE`, `Screen.WhatsYours.route`, `Screen.ReflectionFlow.ROUTE`, `Screen.ReflectionDetail.ROUTE`. Everything else stays open.
- Settings data actions that always ask for the unlock when the lock is on (no unlock window): the `.txt` export, Back Up Now, turning Automatic Backup on or choosing its file, Restore From Backup (before the file picker), Restore That Backup, Replace That Backup, Clear journal and Deactivate (before their confirm dialogs). Turning App Lock off always asks too.
- Text only through `AtaraxyText` roles (`TypographyGuardTest`); strings in `res/values/strings_settings.xml` (Settings) or `strings.xml` (prompt titles); American English.
- Gradle on this machine: run outside the sandbox with `JAVA_HOME="/c/Program Files/Android/Android Studio1/jbr"` (or `Android Studio/jbr` if its `lib/jvm.cfg` exists), `TMP=TEMP=C:\tmp`, `JAVA_TOOL_OPTIONS="-Djdk.net.unixdomain.tmpdir=C:/tmp -Djava.io.tmpdir=C:/tmp"`. Devices: `adb -s emulator-5554` only.
- Branch `feat/app-lock`, stacked on `feat/backup-restore`, worktree `.claude/worktrees/app-lock`.

## Review Focus

1. **A configuration change (rotation, dark-mode switch) while a locked screen is open** must not relock or re-prompt; only a real trip to the background counts. *Test in Task 2.*
2. **The user cancels the unlock prompt** (back gesture, "Cancel", too many attempts): they return to where they came from, and the locked content is never drawn, not even for a frame. *Test in Task 3.*
3. **A deep link or notification opens a locked route directly** (cold start straight into Journal): it's still gated, and cancel lands on Home rather than an empty back stack. *Test in Task 3.*
4. **The phone's screen lock is removed after App Lock was turned on**: locked screens must not become unreachable forever; App Lock stops gating and Settings shows it as unavailable. *Test in Task 1.*
5. **Restoring a backup made while App Lock was on** doesn't turn the lock on, and turning App Lock on doesn't change the next backup's content. *Test in Task 1.*

**Interfaces:**
- Produces:
  - `interface DeviceAuthenticator { fun isDeviceSecure(): Boolean; suspend fun authenticate(activity: FragmentActivity, title: String): Boolean }` (true = unlocked; false = cancelled, failed or unavailable)
  - `@Qualifier annotation class LockPrefs`
  - `@Singleton class AppLock @Inject constructor(@LockPrefs dataStore: DataStore<Preferences>, authenticator: DeviceAuthenticator, clock: Clock)` with:
    - `val enabled: StateFlow<Boolean>` — stored flag AND `authenticator.isDeviceSecure()` (Review Focus 4)
    - `val isUnlocked: StateFlow<Boolean>` — true when not enabled, or after `markUnlocked()` until relocked
    - `suspend fun setEnabled(on: Boolean)` (stores the flag; turning on also marks unlocked)
    - `fun markUnlocked()`
    - `fun onBackgrounded()` / `fun onForegrounded()` — relock if `clock` advanced by `RELOCK_AFTER` (`Duration.ofSeconds(60)`) or more between them
    - `fun isAvailable(): Boolean = authenticator.isDeviceSecure()`
  - Preference key: `booleanPreferencesKey("app_lock_enabled")`.
